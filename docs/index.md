# Google Drive Provider

An independently maintained provider for Google Workspace Shared Drive administration using Google's official Drive API v3 Go SDK. The provider supports both OpenTofu and Terraform. This initial release is experimental; live Workspace acceptance has not yet been completed.

Use the full `registry.opentofu.org/solcreek/gdrive` source address with either CLI. Registry availability depends on completion of the initial OpenTofu registration.

## Example Usage

```terraform
terraform {
  required_providers {
    gdrive = {
      source  = "registry.opentofu.org/solcreek/gdrive"
      version = "~> 0.1"
    }
  }
}

# Use Application Default Credentials.
provider "gdrive" {}

# Keyless domain-wide delegation uses ADC to impersonate a service account,
# then acts as the specified Workspace user.
provider "gdrive" {
  alias                       = "admin"
  impersonate_service_account = "drive-automation@example-project.iam.gserviceaccount.com"
  subject                     = "admin@example.com"
  use_domain_admin_access     = true
}
```

## Authentication

The default is Application Default Credentials. Explicit alternatives are an OAuth access token, a service-account key file, or ADC-backed service-account impersonation. The `subject` setting enables Workspace domain-wide delegation and requires either a service-account key or impersonation target.

The provider requests the `https://www.googleapis.com/auth/drive` scope. Enable Drive API in the Google Cloud project. For keyless impersonation, enable IAM Service Account Credentials API and grant the source identity the required service-account signing/token permissions. Authorize the service account's OAuth client ID and Drive scope in the Workspace Admin Console when using domain-wide delegation.

Google Cloud IAM roles do not grant Drive content access. `use_domain_admin_access` applies only to API operations supporting domain administration. Folders still require appropriate content permissions.

See the repository's [authentication guide](https://github.com/solcreek/terraform-provider-gdrive/blob/main/docs/authentication.md) for configuration and token handling.

## Lifecycle behavior

Shared Drives and folders default to `deletion_protection = true`. Apply `false` before destroying them. Shared Drives must be empty; folder destruction moves the folder and its contents to trash. The provider does not permanently delete folder contents.

Permissions are managed individually. Import existing direct grants before managing them. Inherited-only grants must be changed on their originating parent. Avoid concurrently managing the same permission through multiple resources, provider aliases, or separate state files.

Read operations remove managed resources from state on HTTP 404. Google can also return 404 when an object is inaccessible; check authentication and access before approving a replacement plan. HTTP 403 retains state and reports an error.

### Optional

- `access_token` (String, Sensitive) Short-lived OAuth access token. GDRIVE_ACCESS_TOKEN fallback; no automatic refresh.
- `credentials_file` (String) Path to a service-account key. GDRIVE_CREDENTIALS_FILE fallback. Prefer ADC or keyless impersonation.
- `impersonate_service_account` (String) Service-account email to impersonate using ADC. GDRIVE_IMPERSONATE_SERVICE_ACCOUNT fallback.
- `subject` (String) Workspace user for domain-wide delegation. GDRIVE_SUBJECT fallback. Requires key or impersonation.
- `use_domain_admin_access` (Boolean) Use domain administrator access for Drive and permission operations. Defaults to false; does not grant access to file contents.
